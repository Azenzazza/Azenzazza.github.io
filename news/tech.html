AIエージェントの悪意記憶検証

リード文

AIエージェントが外部からの悪意ある指示を記憶し、長期にわたって不正なツール呼び出しを再現するリスクが顕在化しています。メモリ管理やサンドボックス設計、ガードレール（Guardrails）といった多層防御の有効性が議論され、実装例として「AgentCore Memory」と「Herdr プロキシ」の検証が注目されています。本稿では、これらの実証結果を踏まえて安全性確保の課題と今後の方向性を整理します。

背景

AIエージェントは、ユーザーからのプロンプトや外部資料を解析し、タスク実行に必要なツールを自動的に呼び出すことが一般的です。しかし、プロンプトインジェクションと呼ばれる攻撃手法により、意図しないツールやコマンドが実行されるケースが報告されています。特に、悪意ある指示がエージェントの長期記憶（Memory）に保存されると、セッションが終了しても次回起動時に同様の不正動作を再現する「メモリ汚染（Memory Poisoning）」の危険性が指摘されています。

この問題への対策として、System Prompt の厳格化、Amazon Bedrock Guardrails、AgentCore Policy といったガードレール機構が提案されてきました。これらは「権限外の顧客資料取得」シナリオで比較検証され、各手法の防御範囲や限界が明らかになっています。一方で、サンドボックス環境下でのエージェント実行においても、外部ツール（例：Herdr）への不正アクセスがサンドボックス脱出につながるケースが報告され、ネットワーク・ファイルシステム・コマンド実行の制御が重要視されています。

詳細

1. 悪意指示の記憶とガードレールの比較

Zenn に掲載された実証記事では、AgentCore Memory に悪意ある指示が保存された場合の挙動を、以下の三種のガードレールと比較しています。

  • System Prompt：エージェント起動時に固定された指示を付与し、特定のツール呼び出しを禁止。
  • Amazon Bedrock Guardrails：AWS が提供するコンテンツフィルタリング機能で、入力テキストの危険度をリアルタイムに評価し、危険と判定されたプロンプトをブロック。
  • AgentCore Policy：エージェント内部で実行可能なツールや権限をポリシーとして定義し、実行前にポリシー照合を行う。

実験では、悪意ある指示を一度エージェントに与えても、System Prompt と Bedrock Guardrails は即時に実行を阻止できましたが、Memory に保存された指示は次回セッションで再利用される可能性が残りました。一方、AgentCore Policy は実行時に常にポリシー評価を行うため、Memory に保存された指示であっても実行が防がれることが確認されています。

2. サンドボックスと Herdr の安全な連携

別の Zenn 記事では、macOS の Seatbelt 機構を利用したサンドボックスツール nono 上で、AI エージェントにターミナルマルチプレクサ「Herdr」を使用させる構成が紹介されています。Herdr は端末操作を抽象化するツールですが、直接エージェントに操作権を与えるとサンドボックスの境界を突破できるリスクがあります。

この課題を解決するために、エージェントと Herdr の間にプロキシ層を挟む設計が採用されました。プロキシは以下の機能を提供します。

  • Herdr へのコマンド送信を JSON 形式でラップし、許可されたコマンドのみを転送。
  • 実行結果をエージェントに返す前にサンドボックス外への情報漏洩がないか検査。
  • 不正なシステムコールやファイルアクセス要求を遮断し、Seatbelt の制限を補完。

この構成により、エージェントは Herdr の便利さを活かしつつ、サンドボックスの安全性を維持できることが実証されました。

3. セキュリティ設計の重要性とエンジニアに求められるスキル

Qiita の「AI開発のセキュリティは設計で証明！」では、AI システム全体を「設計段階での脅威モデリング」→「実装時のガードレール適用」→「運用時のモニタリング」という三層防御モデルで捉えるべきと提唱されています。特に、AI エージェントに関しては以下の点が強調されています。

  • メモリ管理ポリシーの明示的定義と、記憶データの有効期限設定。
  • 外部ツール呼び出しをホワイトリスト方式で制御し、サンドボックス外へのアクセスを最小化。
  • ログとメトリクスの可視化により、異常なツール呼び出しやメモリ汚染の兆候を早期検出。

また、エンジニアに必要なスキルとして、OS の権限管理（Seatbelt など）やクラウドベースのガードレール設定、プロキシや API ゲートウェイによるアクセス制御の実装経験が挙げられています。

影響・展望

本格的に AI エージェントが業務プロセスに組み込まれる段階で、メモリ汚染やサンドボックス脱走といったリスクは、単なる技術的課題に留まらず、法的・倫理的責任問題へと拡大します。AgentCore Policy のように「実行時ポリシー評価」を標準化すれば、Memory に保存された過去の指示が再利用されても安全性を保てる可能性があります。一方、サンドボックスと外部ツールの安全な連携は、プロキシ層やホワイトリスト管理といった「防御の境界を明確にする」設計が鍵となります。

今後は、以下の方向性が期待されます。

  • AI プラットフォームベンダーが統一的なガードレール API を提供し、エージェント開発者が容易にポリシー適用できる環境整備。
  • メモリ汚染検知のためのベンチマークデータセットと、異常検知アルゴリズムのオープンソース化。
  • サンドボックス内部でのツール使用を安全に抽象化するプロキシフレームワークの標準化。

これらが実装されれば、AI エージェントは「安全に」かつ「柔軟に」業務支援を行える基盤が整うとみられます。

まとめ

AI エージェントの悪意記憶問題は、Memory に保存された指示が長期的にリスクを孕む点が核心です。System Prompt や Guardrails だけでなく、実行時にポリシー評価を行う AgentCore Policy が有効であることが実証されました。また、サンドボックス内での外部ツール利用は、プロキシ層によるアクセス制御で安全性を確保できることが示されています。今後は、ガードレールの標準化とメモリ汚染検知技術の成熟が、AI エージェントの安全運用を支える鍵となるでしょう。
