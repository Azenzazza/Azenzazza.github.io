Microsoft Foundry で AI エージェント設計

リード文

Microsoft が提供する AI 開発プラットフォーム Foundry でエージェントを設計する際に必ず検討すべき5つのポイントが明確化された。データ保存先、エージェント生成方式、外部ツール連携、権限設定、ネットワーク構成という要素が相互に影響し合うことから、実務での導入・運用を成功させるには全体像を俯瞰した設計が不可欠となっている。

背景

AI エージェントは、コード生成から業務判断まで幅広いタスクを自動化できることから、開発現場に急速に浸透している。2026 年に入ってからは、OSS 開発の加速や、AI がコードレビューや認可ロジックの実装を担うケースが増加し、エージェントの設計・管理がプロジェクト成功の鍵となっている。

しかし、エージェントは単体で完結するわけではなく、会話履歴や生成ファイルの永続化、外部ツール（例：tmux、iTerm2）とのシームレスな連携、さらに組織内の権限体系やネットワークポリシーとの整合が求められる。そのため、設計段階で「どこに保存するか」「どの方式で作るか」などを曖昧にすると、後工程でのデータ漏洩リスクや運用コストの増大につながる。

このような課題に応える形で、Microsoft が公式ドキュメントにまとめた「Foundry で AI エージェントを設計するときに決める5つのこと」は、実務者向けの実践的ロードマップとして注目を浴びている。

詳細

1. 会話履歴・ファイルの保存先選定

Foundry では、プロジェクト単位でリソースを作成し、その下にエージェントを配置する構造になっている。保存先は Azure Blob Storage、Cosmos DB、あるいは Microsoft Teams のファイル領域など複数から選択でき、選択肢はエージェントのスケールやデータ保持ポリシーに直結する。

たとえば、機密性の高い会話履歴は暗号化対応の Blob に保存し、検索性が重視されるファイルは Cosmos DB のコンテナに格納するといったハイブリッド構成が推奨される。

2. エージェント作成方式の決定

Foundry では「コードベース」「ノーコード」「ハイブリッド」の三つの作成方式が提供されている。コードベースは開発者が Python や TypeScript でロジックを記述し、細かなチューニングが可能。一方、ノーコードは UI 上でフローを組むだけでエージェントを構築でき、非エンジニアでも活用しやすい。

実務では、コアロジックはコードベースで実装し、補助的なタスク（例：定型レポート生成）はノーコードで迅速に追加するハイブリッド手法が多く採用されている。

3. 接続ツール・インテグレーションの選択

エージェントは外部ツールと連携してタスクを実行することが前提になる。Zenn に掲載された実例では、iTerm2 のタブや tmux セッションを制御し、開発者が「コードを書く」から「判断を委任する」までのフローを自動化した。

このようなツール連携は、Foundry の「Tool Connector」機能を介して API 呼び出しや CLI 実行を行うことで実現でき、エージェントが生成した指示を直接シェルに流す形が一般的だ。

4. 権限・認可設計

AI エージェントがデータにアクセスする際の権限は、Azure AD のロールベースアクセス制御（RBAC）で細分化できる。たとえば、コード生成エージェントはリポジトリへの書き込み権限のみ、機密情報検索エージェントはシークレットストアへの読み取り権限だけというように、最小権限の原則に沿った設定が求められる。

実務例として、Claude Code を活用したリリース作業では、AI が全コードを読むわけではなく、レビュー対象箇所を限定することで認可リスクを低減した。

5. ネットワーク構成とセキュリティ

Foundry のエージェントは VNet 内で動作させることが推奨され、外部 API へのアクセスはプライベートエンドポイント経由で行う。これにより、データがインターネット上に流出するリスクを抑えつつ、内部サービスとの高速通信が確保できる。

また、Gemini 4 Neon と Claude Code・Codex CLI の比較実験では、トークン数が増大するとネットワーク遅延が顕在化するケースが報告されており、エージェントの設計段階で帯域幅やレイテンシ要件を見積もる重要性が示唆されている。

影響・展望

AI エージェント設計の標準化が進むことで、開発チームは「AI に任せる領域」と「人が介在すべき領域」の境界を明確に描けるようになる。OSS 開発におけるコード生成エージェントの導入例や、認可ロジックを AI に委託した実装事例は、今後の開発プロセスを大幅に効率化する可能性を示している。

一方で、権限設定やネットワーク構成のミスはセキュリティインシデントにつながるリスクがあるため、設計フレームワークの遵守が求められる。Microsoft が提供する 5 つの設計項目は、これらリスクを体系的に管理するためのチェックリストとして、企業の AI 活用戦略に組み込まれることが予想される。

まとめ

Microsoft Foundry で AI エージェントを設計する際の 5 つの決定事項は、データ保存、エージェント生成方式、ツール連携、権限・認可、ネットワーク構成という全体像を網羅している。実務での成功事例は、ハイブリッド作成方式と最小権限の徹底、プライベートネットワーク活用が鍵であることを示唆している。これらを踏まえた設計が、今後の AI エージェント活用を加速させるだろう。
