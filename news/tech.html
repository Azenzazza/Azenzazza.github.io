AIペネトレーションテストで自動化を実現

リード文

サイバー攻撃の高度化とAI技術の急速な進展が交錯する中、Zennチームは「OpenCode＋Docker＋GitHub Actions」を組み合わせた全自動AIペネトレーションテストを実装した。AIエージェントがコードレビューや脆弱性診断を自律的に行うことで、開発サイクルに組み込める「安全性」と「自動化」の両立が実現された。本稿では、同プロジェクトの技術的概要と、AIエージェントの危険行動抑止策、そして業界全体への波及効果を整理する。

背景

近年、サイバー攻撃は「AIをフル活用」した手法へとシフトし、脆弱性が発見されてから実際に悪用されるまでの時間が従来に比べて大幅に短縮されつつある（NetSecurity 2026年8月記事）。このような状況下で、開発チームは「脆弱性検出＝手動」から「脆弱性検出＝自動」への転換を迫られている。さらに、AIエージェントに対して「⚪︎⚪︎はしないで」と単に禁止指示を出すだけでは、期待通りに行動させられないケースが報告されている（Qiita「AI Agent の危険行動を制限する 5 つの方法」）。この課題は、AIが生成するコードや操作指示が予期せぬリスクを伴う可能性を示唆しており、実装時の安全策が不可欠である。

加えて、AI導入が「40年分の技術負債」を顕在化させるという指摘（Hacker News「AI is forcing us to pay off 40 years of technical debt」）もあり、古いコードベースや非標準的な開発プロセスがAIの効果を阻害するリスクが指摘されている。こうした背景から、AIエージェントを安全に、しかも自動化された形で運用する技術的枠組みへの関心が高まっている。

詳細

Zenn の全自動ペネトレーションテストは、以下の三要素で構成されている。

  • OpenCode：AIがコード全体を解析し、潜在的な脆弱性を抽出するフレームワーク。
  • Docker：テスト環境をコンテナ化し、環境依存の差異を排除。毎回クリーンな状態でテストを実行できる。
  • GitHub Actions：CI/CD パイプラインに組み込み、プルリクエストごとの AI レビューに加えて、週次で自動的にペネトレーションテストを走らせる。

この仕組みにより、開発者は PR のマージ前に AI が生成したセキュリティレポートを確認でき、脆弱性が検出された場合は即座にフィードバックが返る。さらに、週次の自動テストは「実運用に近いシナリオ」をシミュレートし、AI エージェントが攻撃者視点でシステム全体を走査する。

しかし、AI エージェントの「危険行動」を抑止するためには、単なる「しないで」指示だけでは不十分であることが Qiita の調査で明らかになっている。具体的な対策としては、次の五つが提案されている。

  1. **明示的な許可リスト**（ホワイトリスト）を用意し、許可された操作のみを実行させる。
  2. **コンテキスト制御**：AI が参照できるデータやコマンドを限定し、意図しない権限昇格を防止。
  3. **監査ログの強化**：全ての AI の指示と実行結果を記録し、事後分析を可能にする。
  4. **人間のレビュー層**：AI が出した提案は必ず人間が確認し、承認するフローを設ける。
  5. **モデルの安全化**：Claude Code や Antigravity CLI といった特定のモデルに対し、危険行動抑止用のファインチューニングを実施。

Zenn の実装は、GitHub Actions のジョブ定義に「安全性チェック」ステップを追加し、上記のうち「許可リスト」と「監査ログ」を自動的に適用している点が特徴的である。これにより、AI が生成した攻撃シナリオが実際に実行される前に、事前に安全性が検証される仕組みが整備された。

また、AI エージェントが高速に情報を取得できる基盤として、Qiita の「Decision RAG」も注目されている。Decision RAG は、判断特化型モデル（例：Jev）を検索エンジンに組み込み、従来の RAG（Retrieval‑Augmented Generation）に比べて「速い・安い・上手い」特性を持つとされる。Zenn のペネトレーションテストにおいても、脆弱性情報の検索や攻撃パターンの推論に Decision RAG を活用すれば、テスト実行時間を短縮しつつ、より精度の高い結果が期待できる。

さらに、Hacker News の議論（「Gemini trains on chat history」）からは、AI がユーザーのチャット履歴を学習に利用するケースが指摘されており、プライバシーとセキュリティの二重課題が浮き彫りになっている。Zenn の自動テストは社内リポジトリ内のコードに限定して実行されるため、外部データの流出リスクは低減できるが、同様のプライバシー保護策が他の AI セキュリティツールでも求められる。

影響・展望

全自動 AI ペネトレーションテストの実装は、以下のような波及効果をもたらすと考えられる。

  • **開発サイクルの短縮**：脆弱性検出が PR 時点で完了するため、修正コストが大幅に削減される。
  • **技術負債の顕在化**：AI が自動的に古いコードや非標準実装を指摘することで、長年放置されてきた技術負債が可視化され、リファクタリングの優先順位付けが容易になる。
  • **安全性の標準化**：危険行動抑止のベストプラクティス（許可リスト、監査ログ、人間レビュー）が CI/CD に組み込まれることで、業界全体での安全基準が統一される可能性がある。
  • **AI 活用のハードル低減**：Docker と GitHub Actions という一般的なツールチェーンで実装できるため、スタートアップや中小企業でも導入しやすくなる。

今後は、Decision RAG のような高速検索モデルや、AI エージェントの「安全性プロファイル」を自動生成する仕組みが加わることで、さらに高度な自動化とリスク管理が同時に実現できると予想される。また、AI が生成した攻撃手法が実世界で悪用されるリスクを抑えるため、AI の学習データや実行環境に対するガバナンスが法的・倫理的に問われる局面も増えてくるだろう。

まとめ

サイバー攻撃が AI を活用して高度化する中、Zenn の「OpenCode＋Docker＋GitHub Actions」ベースの全自動ペネトレーションテストは、開発フローに安全性と自動化をシームレスに統合した先駆的事例である。危険行動抑止の具体策や Decision RAG の導入可能性を踏まえると、今後の AI エージェント活用は「安全な自動化」へと収束していくと見込まれる。
