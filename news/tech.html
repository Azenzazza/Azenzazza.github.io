Claude Codeの新しい監査コマンド

リード文

AI がコードを自動生成し開発効率を飛躍的に向上させる中、生成物の安全性と品質を保証する仕組みが求められています。Claude Code が 2026 年 9 月 25 日にリリースした新しい監査コマンド「/doctor」‑「prompt‑audit」は、AI が書いたコードやプロンプトを体系的に点検できる機能として注目を集めています。本稿では、このコマンドの概要と、同時期に進化した他の AI コード支援ツールとの関係を整理し、業界への影響を考察します。

背景

近年、Playwright の「Test Agents」や VS Code 用 Claude Code 拡張機能の頻繁なアップデートなど、AI を活用した開発支援ツールが次々に登場しています。Playwright Test Agents は GitHub Actions と連携し、E2E テストの生成・修復を自動化することで、テスト保守の負担を軽減します。一方、Claude Code の拡張機能は、利用者が頻繁にアップデートを受け取るほど活発に進化しており、エフォート（計算リソースの投入度）の調整が重要なテーマとなっています。こうした背景の中で、AI が生成したコードやプロンプトの品質・安全性を検証する仕組みが不足しているとの指摘が高まり、Claude Code チームは監査コマンドの追加に踏み切りました。

詳細

Claude Code 2.1.283（2026‑09‑25）の changelog には、/doctor prompt‑audit（/checkup prompt‑audit） が新たに加わったと記載されています。このコマンドは、ユーザーが作成した CLAUDE.md ファイルやプロンプトを対象に、以下のようなチェックを自動で実施します。

  • プロンプトの構文エラーや不適切な指示の有無
  • AI が参照すべきスキル（例：スキル49本）が正しく認識されているか
  • エフォート設定がタスクに対して適切かどうかの評価

実装は CLI 形式で提供され、開発者はローカル環境や CI パイプラインに組み込むだけで監査を自動化できます。例えば、GitHub Actions のジョブに /doctor を組み込めば、プルリクエスト時にプロンプトの品質が自動的に検証され、問題があればコメントでフィードバックが返されます。

この機能は、先行する Playwright Test Agents の「承認と検証」フローと概念的に類似しています。Playwright では、エージェントが生成したテストコードを人間が承認し、必要に応じて修正しますが、Claude Code の監査コマンドは AI が生成したプロンプト自体を機械的に検証し、スキルやエフォート設定のミスマッチを事前に検出します。結果として、AI が出力したコードの安全性が高まり、開発フロー全体の信頼性が向上すると期待されています。

また、VS Code 拡張機能の更新頻度が高い点も注目すべきです。Marketplace の API で取得したデータによれば、短期間に多数のバージョンがリリースされており、ユーザーは常に最新の監査ロジックやエフォート調整機能を利用できる環境が整備されています。これにより、エフォートを「高」や「低」だけでなく、タスクに合わせた細かなチューニングが可能となり、監査コマンドとの相乗効果が期待されます。

影響・展望

監査コマンドの導入は、AI コード生成ツール全体に品質保証の標準化を促す可能性があります。開発チームは、テスト自動生成（Playwright）やコード補完（Claude Code）といった AI 支援機能を利用しつつ、監査プロセスを CI に組み込むことで、ヒューマンエラーやセキュリティリスクを低減できます。

さらに、Microsoft が同日に発表した Copilot の大規模アップデートと同様に、AI アシスタントが「生成」だけでなく「検証」まで担うエコシステムが形成されつつあります。今後、監査機能が他のプラットフォームにも拡張され、統一的なプロンプト品質指標が業界標準になる可能性があります。

まとめ

Claude Code の新しい監査コマンドは、AI が生成したプロンプトやコードの品質を機械的に点検する重要なツールです。Playwright Test Agents の自動テスト生成や VS Code 拡張機能の頻繁な更新と相まって、開発現場における AI 活用の安全性と信頼性が格段に向上すると期待されています。今後は監査機能の標準化が進み、AI コード生成ツール全体の成熟化が加速する見込みです。
