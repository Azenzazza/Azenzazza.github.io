AIに書かせた、が全然AIが書いてない件

リード文

AIエージェントがコード生成や運用タスクを自動化する動きが加速している。実務での活用例として、給与システムの意思決定が勝手に変わるケースや、社内クラウドエージェント基盤の構築・トークン削減手法、複数タスクを一つのチャットに集約する「いちょまる」など、さまざまな実装が報告されている。本稿では、これらの事例を横断的に整理し、現場が直面する課題と今後の展望を探る。

背景

近年、Claude Code、Codex、GPT‑3.5 Turbo など高度な大規模言語モデル（LLM）を活用したエージェントが、開発者の作業を補助するツールとして広がっている。特に「AI‑Native」な開発環境を目指す企業が増え、コード生成だけでなく、仕様書の自動更新や運用フローの自動化までを一括で担うケースが増加中だ。AIエージェントは、決定情報（ADR）や実装仕様（OpenSpec）を読み取り、指示に従ってコードを書き、さらにはその結果を別のシステムへ反映させるという一連の流れを自律的に実行できると期待されている。

しかし、エージェントが自律的に動くことは、意図しない意思決定変更や情報の食い違いといった新たなリスクも伴う。実務での導入事例が増えるにつれ、こうした課題への対策が急務となっている。

詳細

1. 意思決定が勝手に変わるパターンと対策

Dress Code の HR Force チーム（給与ドメイン担当）が報告したケースでは、Claude Code や Codex に日常的にタスクを委任している最中に、以下の5つのパターンで決定が予期せず変化した。

  • 仕様質問が「仕様変更指示」として記録された。
  • 承認していない提案が次工程で「決定済み」と扱われた。
  • エージェントが過去の ADR を参照せず、矛盾した判断を下した。
  • 外部環境（例：Slack のメッセージ）と内部状態が同期されず、状態遷移が失われた。
  • 自動生成されたコードが既存のテストケースと不整合を起こした。

対策としては、エージェントに対し「決定情報は必ず ADR に書き込み、変更は人間の承認を必須にする」フローを組み込むこと、そして「OpenSpec の仕様書を読み込む前に最新の ADR を再取得させる」仕組みを導入した。

2. 社内クラウドエージェント基盤の構築例（Uvin）

Ubie の CTO が語るように、2023 年に GPT‑3.5 Turbo がリリースされた頃から、Web UI や Slack を起点に動くクラウドエージェント基盤を内製し、2025 年には「Software Factory」へ向けたエンジニアリングエージェント Uvin の開発に着手した。

基盤は、エージェントが「Bet」する（＝提案・実行）プロセスを統一的に管理し、タスクの割り当て・結果の集約・再利用を可能にする。これにより、複数チームが同一のエージェントを横断的に利用でき、開発サイクルの短縮とナレッジの共有が実現された。

3. トークン使用量の削減テクニック

Sae 氏は Claude Code のトークン消費が多いことに着目し、compact 設定と離席時の自動コンパクト化を組み合わせた結果、トークン使用量が約 40% 減少したと報告している。実験は 10/13〜11/9 の 15 日間と、設定変更後の 11 日間で比較し、作業内容は概ね同等であった。

この手法は、エージェントが生成する出力を必要最小限に抑えることで、コスト削減と応答速度向上の両立が可能になる点が注目される。

4. 複数担当・定期実行を一括管理する「いちょまる」

OpenCode を拡張し、親セッション（まとめ役）から子セッション（担当）へタスクを振り分け、結果を一つのチャットに集約する「いちょまる」も公開された。利用者は常に同一のチャット窓口に話しかけるだけで、AI が適切な担当へ指示を転送し、完了報告をまとめ役に返す仕組みだ。

この設計は、同時進行する複数の依頼や定期的なリマインド作業を手動で再入力する手間を削減し、作業の可視化と履歴管理を容易にする。

5. コード脆弱性自動修正エージェント「CodeMender」

2026 年 11 月、Google Cloud のブログで紹介された CodeMender は、GitHub のプルリクエスト（PR）に組み込むことで、AI が脆弱性を検出し自動で修正する機能を提供する。実装例は Qiita 記事で取り上げられ、新卒エンジニアが基礎学習に活用できる点が強調されている。

このように、AI がコード品質向上に直接関与するケースが増えると、従来のコードレビュー工程に変革が起きる可能性がある。

影響・展望

AI エージェントによるコード・運用自動化は、開発スピードの向上とコスト削減を実現しつつ、意思決定の透明性やトークン消費といった新たな課題も浮き彫りにしている。組織は「エージェントの出力を人間が必ずレビューする」フローや「トークン節約設定の標準化」など、ガバナンスと最適化の両輪で運用を整備する必要がある。

今後は、エージェントが「決定情報」を自律的に更新できるようになると同時に、変更履歴の自動追跡やコンフリクト検出機能が標準化される可能性がある。さらに、CodeMender のようにセキュリティ領域へ AI が本格参入すれば、脆弱性対応のスピードが飛躍的に向上し、開発者は価値創造に専念できる環境が整うとみられる。

まとめ

AI エージェントはコード生成から運用自動化まで幅広く活用され、実務での効果と課題が同時に顕在化している。意思決定の自動変更リスクへの対策、トークン削減のテクニック、タスク統合チャット「いちょまる」や脆弱性修正エージェント「CodeMender」など、具体的な実装例が示すように、ガバナンスと最適化を両立させた運用が今後の鍵となる。
