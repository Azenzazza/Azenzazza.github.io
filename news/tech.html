自分の代わりに動くAgentへ

リード文

AIエージェントが「自分の代わりに」コードを書き、テストを走らせ、改善まで行う時代が到来しつつある。Claude CodeやCodexを活用した自律的なハーネスや、pstack のような品質保証フレームワークが登場し、開発の自動化が加速している。一方で、コード品質の担保や運用コスト、ワークフロー設計といった課題も顕在化しており、実務での適用方法が議論の焦点となっている。

背景

過去 1 年で大規模言語モデルは飛躍的に性能を向上させ、AI エージェントは「コード修正」や「テスト実行」まで人間の逐次指示を必要としなくなった（Qiita「人間がボトルネックになった時代のAIエージェント設計」）。しかし、複数のエージェントを並行して運用すると、期待した速度向上が得られないケースが増えている。指示の重複や過去作業の追跡不能、エージェント間で設定が分散する問題が顕在化し、開発者は「エージェントに任せる範囲」と「人が介在すべきポイント」の境界線を再定義する必要に迫られている。

詳細

自律改善ハーネスの試み

Zenn に掲載された記事「自分の代わりに動くAgentへ」では、2026 年 7 月に個人用ハーネスの構築が開始されたと報告されている。このハーネスは Claude Code と Codex を組み合わせ、過去に指示した内容をエージェントが記憶し、同一タスクだけでなく多様な作業に対して自律的に行動できるよう設計された。従来の ADE（Agentic Development Environment）では、ターミナルごとにエージェントを分散させるため、指示の重複や作業履歴の欠如が問題となっていたが、ハーネスは「一度伝えたことは覚えている」ことを前提に、指示回数の削減と作業の可視化を実現しようとしている。

品質保証のための pstack

同じく Zenn に掲載された「pstack 完全ガイド」では、AI エージェントが自信満々に生成したコードが未検証のまま提供されるケースが指摘されている。pstack は元 React コアチームのエンジニアが実践している手法を体系化し、AI が書くコードの品質を担保するためのワークフローを提示している。具体的には、コード生成後に自動テストとスタティック解析を組み合わせ、結果をエージェントにフィードバックすることで、エージェント自身が改善サイクルを回す仕組みを構築する。これにより「雑なコードを書かせない」だけでなく、エージェントが自律的に修正提案を行うようになる。

役割分担と継続的改善

Qiita の「AIに役割を持たせたワークフローを、使うたびに直していたら、止まらなくなった話」では、AI に単なるコード生成以上の役割—要件整理、実装方針策定、レビュー、修正—を持たせる試みが語られている。実際に、Claude Code や Codex に対し、段階的にタスクを割り当て、各フェーズで人間が評価・修正を行うことで、エージェントが「自律的に」次の工程へ進むプロセスが構築された。これにより、エージェントは単なるツールから、開発プロセス全体を横断する「パーソナルエージェント」へと変容しつつある（Qiita「今話題のMuseってなに？」）。

影響・展望

AI エージェントが自律的に作業を進める基盤が整いつつあることで、開発チームは「人がボトルネックになる」領域を削減できる可能性がある。一方で、エージェント間の設定管理や作業履歴の統合、品質保証の自動化は依然として課題であり、pstack のようなフレームワークやハーネスのような記憶機構が標準化されるかどうかが鍵となる。今後は、エージェントが生成したコードとテスト結果を統合的に評価し、継続的に学習させる「自己改善ループ」の実装が主流になると予想される。さらに、エージェントが個人の開発履歴やチームのコードベースを長期的に保持し、プロジェクト全体の技術負債を自動で管理できる段階へと進化すれば、開発コストの大幅削減と品質向上が同時に実現できるだろう。

まとめ

AI エージェントはコード生成を超えて、要件整理からテスト、改善までを自律的に行う基盤を提供しつつある。Claude Code と Codex を組み合わせたハーネスや、pstack による品質保証フレームワークは、エージェントの実務適用を支える重要な要素だ。課題は依然として残るが、エージェントの記憶・自己改善機能が成熟すれば、開発プロセス全体の自動化が加速し、エンジニアは創造的作業に専念できる新たな開発環境が実現する。
