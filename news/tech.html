Claude Codeで自律改善ハーネス

リード文

AIコーディングエージェントが「書く」「テストする」「改善する」一連の作業を自律的に実行するハーネスが登場した。Claude Code と Codex を組み合わせた「自律改善ハーネス」は、指示一回で設計からテストまでを約10分で完走させ、開発者が睡眠中にプルリクエストを大量に生成できる実証実験が報告されている。本稿では、ハーネスの構成要素と実装事例、そして開発現場への波及効果を整理する。

背景

近年、AI がコードを生成・修正する技術は急速に成熟し、Claude Code、OpenAI Codex、OpenCode など複数のエージェントが実務で利用され始めている。従来はエージェントへの指示を都度手動で行い、作業履歴の管理や設定の統一が課題となっていた。特に、複数ターミナル上で同一指示を繰り返す必要がある点や、過去作業の追跡が困難な点が開発効率を阻害していた。

このような課題を解決すべく、NTTデータが 2026 年 7 月に「自律作業のための個人ハーネス」構築に着手したことが注目されている。さらに、AI Engineer CODE 2026（2026 年 11 月 11 日）で poteto 氏が発表した実例では、1 か月で 3,000 本以上のプルリクエストを自動生成し、その多くが開発者の睡眠時間中に処理されたと報告された。これらの背景から、エージェントが単なるコード生成ツールから、開発フロー全体を自律的に走らせる「開発エージェント」へと進化する期待が高まっている。

詳細

本ハーネスは大きく以下の三つの要素で構成される。

  • エージェント統合層（ADE：Agentic Development Environment）：Claude Code と Codex を同一インターフェースで扱える環境を提供し、指示の重複や設定分散を防止する。
  • 自律タスクフロー：コードの設計、実装、テスト（自動テスト 14 件）から、意図的にコードを壊すテスト検証までをシーケンシャルに実行。指示は「1 回」のみで、エージェントが途中で必要な情報を保持しながら次工程へ遷移する。
  • 成果物管理とフィードバック：実行結果やエラー情報をハーネス内部で蓄積し、次回以降の指示に反映させることで、エージェントが自己学習的に改善を続ける。

実装例として、Cursor 公式スキル集「pstack」を Claude Code に組み込んだケースが報告されている。この構成では、指示 1 回で設計からツール実装、テスト実行までを約 10 分で完了し、開発者の介在なしに 3,000 本規模の PR を本番環境へデプロイできたとされる。また、Qiita に掲載された 150 行程度の Python 実装例は、同様のハーネスを自作する際の参考コードとして公開され、エージェントが「コードを読み、ファイルを編集し、テストを実行し、エラーを直す」一連の流れを自律的に処理できることを示している。

これらの事例は、エージェントが単なる補助ツールではなく、開発者の代替としてタスク全体を完結できるレベルに到達したことを示唆している。ただし、現在は「Claude Code と Codex の設定が分かれている」「過去作業の追跡が不十分」といった課題が残っており、ADE の成熟が鍵となる。

影響・展望

自律改善ハーネスの実装が広がれば、以下のような影響が予測される。

  • 開発者の生産性向上：ルーチン的な実装・テスト作業が自動化され、開発者は設計やアーキテクチャといった高付加価値業務に集中できる。
  • リリースサイクルの短縮：エージェントが夜間に PR を生成・マージできるため、デプロイ頻度が上がり、アジャイル開発のスピードが加速する。
  • 品質保証の自動化：自動テスト 14 件やコード破壊テストが標準化されることで、ヒューマンエラーが減少し、コード品質の均一化が期待できる。
  • 新たなスキル要件：エージェントの設定・運用が重要になるため、AI エージェント運用スキルがエンジニアの必須能力として浮上する可能性がある。

今後は、ADE のさらなる統合と、エージェント間の状態共有機構が整備されることで、複数プロジェクトに跨る自律開発が実現する可能性があるとみられる。また、オープンソース化された pstack のようなツールが普及すれば、個人開発者でも同様のハーネスを構築できる環境が整い、開発現場全体の自律化が加速するだろう。

まとめ

Claude Code と Codex を核にした自律改善ハーネスは、指示一回で設計からテストまでを約10分で完走させ、開発者が睡眠中に大量の PR を生成できる実証実験を通じて、AI エージェントの自律開発への転換点を示した。現在は設定分散や履歴管理の課題が残るものの、ADE の成熟とツールエコシステムの拡充により、開発者の生産性向上とリリースサイクル短縮が期待できる。
