Claude Code使用量の実測と料金表の不一致

リード文

AIコード生成ツール「Claude Code」の使用量測定で、実測されたトークン重みが公式の料金表と食い違うことが判明した。5時間ごとにリセットされるセッション制限と週単位の使用制限という二重の枠組みの中で、キャッシュ再読込みやヘッドレス実行も使用量に含まれることが明らかになり、開発者はコスト予測と品質保証の手法を再考せざるを得なくなった。

背景

近年、Claude CodeをはじめとするAIコード生成エージェントが開発現場に急速に浸透し、プロジェクトの生産性向上が期待されている。一方で、利用料金は「使用した分だけ消費する」方式で提供されており、具体的な消費量の算出方法は公開されていない。開発者は、プラン別に設定された「5時間のセッション制限」と「週間使用制限」の二層構造を前提に、実際にどのようにトークンがカウントされるかを把握できず、コスト見積もりに不透明感が残っていた。

この不透明性は、AIエージェントの品質保証にも影響を与える。AIエージェントが生成したコードの品質を評価するには、オブザーバビリティ（観測可能性）を確保し、評価ループを回す手法が必要とされている（Zenn: オブザーバビリティのAIエージェントをどう評価するか）。また、バックエンドの自動テスト戦略がユニットテスト中心からAPIテスト中心へシフトした事例（Zenn: 新規プロダクトのバックエンド自動テスト戦略）は、AIが生成したコードの統合的な品質評価の重要性を示唆している。

詳細

実測実験の概要

筆者はClaude CodeのProおよびMaxプランで、使用量制限の枠がどのように減少するかを条件を揃えた実験で測定した。実験では、以下の二つの制限を対象にした。

  • 5時間ごとにリセットされる「5時間のセッション制限」
  • 週単位でリセットされる「週間使用制限」

実験に使用したのは、Claude CodeのCLIオプションclaude -pやAgent SDKを介したヘッドレス実行である。

キャッシュ再読込み（cache read）の扱い

従来、キャッシュからの再読込みは「使用量」に含まれないと想定されていたが、実測ではトークンが消費されることが確認された。ただし、その重みはトークンの1/40（0.025倍）である。すなわち、キャッシュ再読込みが大量に発生すると、見かけ上の使用量は増加するが、実際の料金計算に与えるインパクトは限定的である。

ヘッドレス実行のコスト

ヘッドレスモード（claude -pやAgent SDK）でも、標準入力・出力のトークンが使用量にカウントされる。これにより、スクリプトやCIパイプラインで自動化されたコード生成を行う場合、意図せぬ使用量増加が起こり得る。

実測と料金表の不一致

公式のAPI料金表は、入力トークンと出力トークンの重みを一定と仮定しているが、実測では「Max 20x」のプランにおいて、実際のトークン重みが表記と異なることが判明した。具体的な数値は公開されていないが、使用量制限の減少速度が想定より速く、結果として利用者は予算オーバーのリスクを抱える可能性がある。

品質保証への波及効果

使用量測定の不透明性は、AIエージェントの品質評価にも波及する。オブザーバビリティを確保し、評価ループを構築する手法（Zenn: オブザーバビリティのAIエージェントをどう評価するか）では、生成コードの正確性だけでなく、実行コストやリソース消費も指標に含める必要がある。さらに、APIテスト中心の自動テスト戦略（Zenn: 新規プロダクトのバックエンド自動テスト戦略）は、AIが生成したエンドポイントの挙動を実際に呼び出して検証することで、使用量と品質の両面を同時に評価できる。

影響・展望

今回の実測結果は、開発者がClaude Codeのコストを正確に予測できない状況を浮き彫りにした。今後は、ベンダー側が使用量計算式を公開し、料金表と実測が一致するよう透明性を高めることが求められる。加えて、AIコード生成ツール全般に対して、使用量と品質を同時にモニタリングするオブザーバビリティ基盤の整備が急務となるだろう。GitHub Copilot SDKが提供するランタイムとエージェントループ（Qiita: GitHub Copilot SDK のランタイムとエージェントループについて）のように、実行環境と評価ループを統合したフレームワークが標準化すれば、使用量と品質の両方を一元管理できる可能性がある。

まとめ

Claude Codeの実測では、キャッシュ再読込みやヘッドレス実行が想定外の使用量に寄与し、公式料金表と食い違うことが確認された。これにより、AIコード生成のコスト見積もりと品質保証の手法が再評価され、オブザーバビリティとAPIテスト中心の評価ループが今後の標準となる見通しである。
