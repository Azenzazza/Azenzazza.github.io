Claude Code のセキュリティベストプラクティス

リード文

AIエージェントとRAG（Retrieval‑Augmented Generation）の進化が、業務自動化のスピードを加速させています。特に、Claude Code の実行環境におけるセキュリティベストプラクティスと、階層ナビゲーション型 RAG とベクトルDB版 RAG の比較結果は、実装選択の重要な指標となります。本稿では、2026年11月時点の公式情報をもとに、Claude Code のサンドボックス・権限管理・MCP 設定を具体的に解説し、RAG 手法の実装上の課題と Personal Agent Protocol が提供する新たな連携モデルを併せて考察します。

背景

近年、生成系 AI が単なる質問応答から、ユーザーの代わりにタスクを実行する「AI エージェント」へと変貌を遂げています。Meta の Muse に代表されるパーソナルエージェントは、予約・買い物・問い合わせといった業務を自律的に処理し、企業側はそれらエージェントと安全に連携できるプロトコルを求めています。そこで注目されたのが、Sierra Japan が提唱する Personal Agent Protocol (Poppy) です。

一方で、AI エージェントが外部情報を参照しながら高精度な回答を生成するための技術として RAG が広く採用されています。従来のベクトルデータベース（ベクトルDB）を用いる手法と、Corpus2Skill を参考にした「階層ナビゲーション型 RAG」の二つが実装上で比較され、どちらが実務に適しているかが議論の焦点となっています。

さらに、AI がコードやシェルコマンドを実行する場面では、実行環境の安全性が不可欠です。Claude Code は、ユーザー権限で Bash コマンドを走らせることができる一方、サンドボックスや権限制御、MCP（Multiple Credential Provider）設定によりリスクを低減する仕組みが提供されています。これらの要素は、AI エージェントと RAG の実装全体における「セキュリティ基盤」として位置付けられます。

詳細

Claude Code のセキュリティベストプラクティス

2026年11月時点の公式ドキュメントと changelog を基に、以下の三点が推奨されています。

  • サンドボックスの有効化：サンドボックスをオンにすると、実行中の Bash コマンドは同一マシン上で動作しますが、アクセスできるファイルや通信先が制限されます。たとえば、Mac のターミナルで起動した場合、対象はその Mac に限定されます。
  • 権限ルールの明確化：Claude Code CLI は、起動ユーザーの権限でコマンドを実行します。権限エスカレーションを防ぐため、必要最小限の権限で実行することが推奨されます。
  • MCP 設定：Multiple Credential Provider を利用し、認証情報をコード内にハードコーディングしない運用を徹底します。ダミーファイルで読み取り制限を確認する手順が公式サンプルとして提供されています。

上記をチェックリスト化すると、以下のようになります。

  • サンドボックスが有効かつ設定ファイルで許可対象を明示
  • 実行ユーザーが必要最小権限であることを確認
  • MCP に認証情報が登録され、コード上に平文が残っていないか検証
  • ダミーファイルで読み取り制限テストを実施し、期待通りのエラーメッセージが出るか確認

階層ナビゲーション型 RAG とベクトルDB版 RAG の比較

「階層ナビゲーション型 RAG」は、LLM が文書の目次や章構造を辿りながら目的情報を探索する手法です。一方、ベクトルDB版は埋め込みベクトルを用いて類似度検索を行います。実装比較は 28 文書・20 問のテストで行われ、正答数は同等でした。

比較のポイントは次の通りです。

  • 失敗段階の可視化：階層ナビゲーション型は「正しい文書に到達したか」「必要箇所を抽出できたか」の二段階で失敗を分析でき、ベクトルDB版は検索結果の類似度が低い場合に失敗と判定されます。
  • 根拠付与の粒度：コメントで指摘されたように、各問の必須根拠を短いスパンで付与し、8000 文字に切り詰めた後に残った根拠の割合を測定すれば、ナビゲーションと証拠選択の失敗をさらに切り分けられる可能性があります。
  • 実装コスト：ベクトルDBはインフラ構築が必要ですが、階層ナビゲーション型は既存の文書構造を活用できるため、初期コストが低いとみられます。

Personal Agent Protocol (Poppy) の位置付け

Personal Agent Protocol は、パーソナル AI エージェントと企業システムをオープンに接続するプロトコルです。Meta の Muse のようにユーザー代行タスクを実行するエージェントが増える中、企業側はエージェントからのリクエストを安全に受け入れ、認可・監査を行う必要があります。Poppy は、リクエストのスキーマ化、認証情報の分離、そして実行権限の細粒度設定を標準化することで、Claude Code のようなローカル実行環境と組み合わせた際のセキュリティリスクを低減できると期待されています。

具体的には、エージェントが「予約作成」や「データ取得」などのタスクを要求した際、Poppy が以下を保証します。

  • リクエストが事前に定義されたスキーマに合致しているかの検証
  • 認証情報は MCP で管理し、エージェント側に平文が渡らないこと
  • 実行権限はサンドボックスと同様に最小化し、必要なファイル・ネットワークへのアクセスだけを許可

影響・展望

Claude Code のセキュリティベストプラクティスが広く採用されれば、AI エージェントがローカルでコード実行するリスクは大幅に低減します。これにより、企業は内部システムへの AI 連携を加速でき、RAG の活用シーンも拡大すると予想されます。

一方、階層ナビゲーション型 RAG とベクトルDB版 RAG の比較結果は、実装選択の指針として有用です。特に、根拠付与の粒度や失敗分析の可視化は、今後の RAG アーキテクチャ設計に組み込むべき重要な要素とみられます。

さらに、Personal Agent Protocol が標準化されれば、エージェントと企業システム間のインターフェースが統一され、サンドボックスや MCP といったセキュリティ機構とシームレスに連携できるエコシステムが形成される可能性があります。

まとめ

AI エージェントと RAG の進化は、業務自動化を次のレベルへと押し上げています。Claude Code のサンドボックス・権限・MCP 設定は、実行時リスクを最小化する必須項目であり、チェックリスト化されたベストプラクティスは即時導入可能です。階層ナビゲーション型 RAG はベクトルDB版と同等の正答率を示しつつ、失敗分析の粒度が高く、実装コスト面でも魅力があります。加えて、Personal Agent Protocol が提供するオープンな連携基盤は、セキュアなエージェント運用の土台となるでしょう。これらの知見を踏まえて、組織は安全かつ効果的な AI 活用戦略を策定すべきです。
